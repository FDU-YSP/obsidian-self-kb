# 动态规划面试指南

动态规划（Dynamic Programming，DP）的关键不是背公式，而是：**定义状态 → 找到最后一步的选择 → 写出转移 → 确定初始化和计算顺序**。

下面按常见面试题型整理典型 LeetCode 题目，再总结通用解题方法。**优先级是备考建议，不代表经过统计的面试出现频率**；建议先掌握基础题型，最后学习区间、状态压缩和数位 DP。

## 一、先判断：什么时候应该考虑动态规划？

当题目同时具备以下特征时，可以优先考虑 DP：

- **存在重复子问题**：不同选择路径会遇到相同的后续问题。
- **状态能概括历史**：知道当前状态，就足以决定后续选择，不需要保留完整过程。
- **状态之间有明确依赖顺序**：例如短前缀到长前缀、小容量到大容量、小区间到大区间。

典型问法是“最多/最少”“是否可行”“多少种方案”。但这些问法只是线索，**并不意味着一定要用 DP**。

| 题目特征              | 优先考虑的方向  |
| ----------------- | -------- |
| 每一步局部最优可以证明导向全局最优 | 贪心       |
| 无权图上的最少步数         | BFS      |
| 需要枚举具体方案，且难以合并状态  | 回溯、搜索    |
| 枚举过程出现大量重复状态      | 记忆化搜索、DP |
| 大问题可以拆分，但子问题基本不重复 | 分治       |

**实用理解：记忆化搜索，是给递归搜索加缓存；递推 DP，是按依赖顺序主动计算这些状态。**

## 三、通用解题流程：每道题都按这六步走

### 第一步：先把暴力解法说清楚

先问自己：“如果不考虑效率，我会枚举哪些选择？”

例如打家劫舍：当前房子只有偷和不偷两种选择。暴力递归中，不同分支会重复求同一段房子的最优解，于是可以缓存。

**从暴力搜索出发，比凭空猜公式更稳。**

### 第二步：用一句完整的话定义状态

推荐句式：

> `dp[状态参数]` 表示，在这些条件下，某个明确子问题的答案。

例如：

- `dp[i]`：前 i 间房能获得的最大金额。
- `dp[i]`：必须以第 i 个元素结尾的最长递增子序列长度。
- `dp[i][j]`：`a[:i]` 和 `b[:j]` 的最长公共子序列长度。
- `dp[i][j]`：闭区间 `[i,j]` 的最长回文子序列长度。

**“前 i 个”和“下标 i”不能混用；开区间和闭区间不能混用。**

### 第三步：枚举最后一步，写出转移

问：“要得到当前状态，最后一步可能是什么？”

以 198 打家劫舍为例，`dp[i]` 表示前 i 间房的最大收益：

dp[i]=max⁡(dp[i−1],  dp[i−2]+nums[i−1])dp[i] = \max\bigl(dp[i-1],\;dp[i-2] + nums[i-1]\bigr)

两项分别表示不偷第 i 间、偷第 i 间。转移要同时满足：**所有合法选择都被覆盖，而且没有加入非法选择。**计数题还必须避免重复计数。

### 第四步：初始化，包括“不可能到达”的状态

|目标|常见初始方式|需要注意|
|---|---|---|
|可行性|`False`，设置合法起点为 `True`|空选择是否可行|
|方案计数|`0`，设置空方案为 `1`|`dp[0]=1` 通常是转移的起点|
|最小值|正无穷，起点为 `0`|不可达状态不能初始化为 0|
|最大值|视语义用 0 或负无穷|必须选、恰好装满等约束下，不能默认都为 0|

例如零钱兑换：金额 0 需要 0 枚硬币，其他金额先设为不可达；最后仍不可达才返回 `-1`。

### 第五步：根据依赖决定遍历顺序

- 依赖 `i-1`：一般从前往后。
- 依赖 `i+1`：一般从后往前。
- 依赖更短区间：按区间长度从小到大，或选择等价的下标遍历顺序。
- 依赖孩子节点：树上后序遍历。
- 依赖 DAG 前驱：拓扑顺序；也可按依赖做记忆化搜索。

**遍历顺序不是习惯，而是依赖关系的结果。**

### 第六步：明确答案位置，再分析复杂度

最终答案可能是 `dp[n]`、全部 `dp[i]` 的最大值、根节点的多个状态之一，或遍历中维护的全局最优值。

常用复杂度估算：

时间复杂度≈状态数量×每个状态的转移代价\text{时间复杂度} \approx \text{状态数量} \times \text{每个状态的转移代价}

例如，LCS 有约 `n×m` 个状态，每个状态常数次转移，因此时间复杂度为 `O(nm)`。如果转移里还进行了字符串切片或哈希计算，也要考虑这些额外成本。

## 四、最常用的解题技巧与方法

### 1. 状态不够用，就补充影响未来的最少信息

|遇到的问题|常见补充状态|
|---|---|
|后续操作取决于手里有没有股票|是否持有|
|不能超过 k 次操作|已用次数或剩余次数|
|乘负数可能让最小值变最大值|同时维护最大值、最小值|
|后续取决于已经选择过哪些元素|集合位掩码|
|不能超过给定数字上界|是否仍受上界约束|

但不要无止境增加维度：**能由其他状态推导出来的信息，尽量不要重复存储。**

### 2. 用“选 / 不选”建立转移骨架

打家劫舍、0/1 背包、子序列计数、树上独立集，都可以从“当前元素选不选”出发。

注意“选择当前元素后，会限制哪些其他选择”。198 限制相邻房屋，416 限制每个元素只能使用一次，115 则要保持字符相对顺序。

### 3. 背包压缩后的遍历方向，决定物品能用几次

下面以正重量、正价值物品的容量不超过 V 的最大价值问题为例：

**0/1 背包：每件最多一次，容量倒序。**

```python
for weight, value in items:
    for capacity in range(V, weight - 1, -1):
        dp[capacity] = max(
            dp[capacity], dp[capacity - weight] + value
        )
```

倒序保证右侧读取的还是“尚未使用当前物品”的上一轮状态。

**完全背包：每件可重复，容量正序。**

```python
for weight, value in items:
    for capacity in range(weight, V + 1):
        dp[capacity] = max(
            dp[capacity], dp[capacity - weight] + value
        )
```

正序允许右侧状态已经使用过当前物品，从而实现重复选择。

**记住的是读写依赖，不只是“倒序 / 正序”口诀。**

### 4. 计数题先判断：顺序不同算不算新方案？

以 518 和 377 的标准题意为例，候选数是互不相同的正整数：

**组合数：外层遍历候选数，内层遍历目标值。**

```python
dp = [0] * (target + 1)
dp[0] = 1
for x in nums:
    for total in range(x, target + 1):
        dp[total] += dp[total - x]
```

**排列数：外层遍历目标值，内层枚举最后一个数。**

```python
dp = [0] * (target + 1)
dp[0] = 1
for total in range(1, target + 1):
    for x in nums:
        if x <= total:
            dp[total] += dp[total - x]
```

例如用 1、2 凑出 3：组合是 `{1,1,1}`、`{1,2}`；排列是 `[1,1,1]`、`[1,2]`、`[2,1]`。

**这些模板有适用前提。**若允许 0、负数、重复候选值，或限制序列长度，必须重新分析是否会重复计数、形成循环或出现无限方案。

### 5. 双序列问题，优先使用“长度前缀”定义

例如 LCS 中，`dp[i][j]` 表示 `a[:i]` 和 `b[:j]` 的答案，实际比较的是 `a[i-1]`、`b[j-1]`。

dp[i][j]={dp[i−1][j−1]+1,a[i−1]=b[j−1]max⁡(dp[i−1][j],dp[i][j−1]),否则dp[i][j] = \begin{cases} dp[i-1][j-1] + 1, & a[i-1] = b[j-1] \\ \max(dp[i-1][j],dp[i][j-1]), & \text{否则} \end{cases}

这样第 0 行、第 0 列自然对应空串，边界更容易统一。编辑距离也是同样的框架，只是目标和转移操作不同。

### 6. 连续性约束，通常要写进状态定义

对比 1143 与 718：

- LCS 不要求连续，不匹配时可以跳过某个字符。
- 最长重复子数组要求连续，不匹配时，对应结尾状态必须归 0。

**很多转移公式的差别，本质上来自状态语义，而不是技巧不同。**

### 7. 正向难描述，就换方向、换视角或做问题转换

|原问题|更好处理的视角|
|---|---|
|环形打家劫舍|拆成两个线性问题|
|目标和中的正负号选择|转为指定和的子集计数|
|石头碰撞后的最小重量|转为两组总和差最小|
|地下城中始终不能死亡|倒推最低入场生命值|
|戳气球时邻居不断变化|枚举区间内最后戳的气球|
|双人轮流拿数字|记录当前玩家相对对手的分差|

转换后必须补齐合法性检查。例如 494 转子集计数时，要检查目标范围和奇偶性，并正确处理值为 0 的元素；这些 0 会增加符号分配方案数。

### 8. 记忆化搜索和递推，按依赖结构选择

|方式|适合场景|注意事项|
|---|---|---|
|记忆化搜索|递归关系自然、状态较稀疏、依赖顺序不直观|缓存键要完整，注意递归深度|
|递推 DP|状态较密集、顺序明确、需要压缩空间|先明确依赖，再安排循环|

缓存的是“相同状态的相同答案”，因此不能遗漏会影响结果的外部条件。记忆化也不意味着可以忽略环：一般 DP 需要无环依赖，循环依赖应另行处理。

### 9. 先写对，再做空间优化

常见优化包括：一维 DP 滚动成几个变量，二维 DP 压缩成一行，以及股票问题压缩掉日期维。

压缩前问清楚：**右侧读取的是上一轮还是本轮的状态？旧值会不会被提前覆盖？**

例如 LCS 压缩成一维时，要额外保存左上角的旧值；0/1 背包则通过倒序避免重复使用当前物品。

如果需要输出具体路径、子序列或选中的物品，还要保存决策或前驱。空间压缩可能让方案恢复变得更复杂。

### 10. 数据规模决定可接受的状态数量

粗略检查：`n` 达到十万量级时，应警惕 `O(n²)`；集合位掩码会带来 `2^n` 个状态；背包的 `O(nV)` 取决于容量数值本身，不只是输入长度。

300 最长递增子序列建议掌握两个层次：先理解 `O(n²)` DP，再学习 `O(n log n)` 的贪心 + 二分。后者中的 `tails` 表示各长度递增子序列的最小可能结尾，**整个 `tails` 数组不保证就是原数组中的一条实际 LIS**。

## 五、面试中最容易丢分的地方

|常见错误|自查问题|
|---|---|
|状态定义含糊|能否用一句话准确说明每个下标和存储值？|
|初始化全写 0|这些状态真的可达吗？是否要求非空或恰好装满？|
|前缀与结尾混淆|状态是否必须包含当前位置？答案在哪里？|
|子串与子序列混淆|不匹配时应该清零，还是可以跳过？|
|0/1 背包容量正序|是否意外让同一物品被使用多次？|
|计数组合与排列混淆|同一组元素换顺序后，题目是否视为新方案？|
|股票原地更新不清晰|转移是否错误混用了当天和前一天的值？|
|区间顺序错误|访问的内部区间是否已经计算完成？|
|空间压缩过早|是否丢失了左上角、上一轮或方案恢复信息？|
|只处理普通输入|是否覆盖空串、单元素、全负数、0、不可达等题意内边界？|

对递推正确性的解释，可以使用归纳法：基础状态正确；假设依赖状态正确；枚举全部合法最后一步，因此当前状态也正确。

## 六、建议的练习路线

如果时间有限，先按下面顺序练习 **20 道核心题**，不要一开始就钻状态压缩和数位 DP。

|阶段|题号与顺序|训练目标|
|---|---|---|
|线性基础|70 → 746 → 198 → 53 → 152|状态定义、选不选、结尾状态、多状态|
|网格与背包|62 → 64 → 416 → 322 → 518 → 377|边界、容量方向、组合与排列|
|序列与字符串|300 → 1143 → 72 → 139 → 516|前驱枚举、双序列、前缀划分、区间|
|状态与结构|122 → 309 → 337 → 312|状态机、额外限制、树形、区间划分|

每道题练完，至少能够不看答案讲清楚：**状态是什么、转移为什么完整、边界如何处理、遍历顺序为什么正确、答案在哪里、复杂度是多少。**

判断是否真正掌握，不是能不能默写代码，而是题目稍作变化——从求最大值改成计数、从可重复改成只能一次、从线性改成环形——你是否还能重新定义状态并推导转移。
